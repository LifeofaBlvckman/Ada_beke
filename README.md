# ADA BEKE — website

*Chic • relaxed • Elegance.* The website for **ADA BEKE**, the free-size fashion brand (Instagram [@byadabeke](https://www.instagram.com/byadabeke/)): four shop pages, online checkout with Paystack, and an admin dashboard for orders and pieces.

| Page | File | What's on it |
| --- | --- | --- |
| Home | `index.html` | Laid out section by section after moyeafrica.com: the three shoot photos changing one at a time (a wide banner on laptops), a sideways row of pieces with arrows, the two collections with their names on the photos, a big photo, a row of looks with names on them, a photo banner with a button, the campaign film filling a dark card with words on it, and links to Instagram, Threads and WhatsApp beside slowly floating photos. Each photo appears only once per page |
| Shop | `shop.html` | All pieces with filters, a product details panel, and the bag |
| About | `about.html` | A big photo with "About ADA BEKE" (as Moye's About page), a photo beside the cream "Our story" panel, a quote from Ada, the full "We're back" letter beside a photo, Chic / relaxed / Elegance |
| Contact | `contact.html` | How to order, a WhatsApp contact form, the free-size guide and questions |
| Your order | `order.html` | Where Paystack sends customers after paying: "Thank you" with their order, or "Payment not completed" |
| Admin | `admin/` | The dashboard: sales, orders, pieces, delivery fees (password protected, hidden from search engines) |

The pages are plain HTML, CSS and JavaScript, and the built pages are committed, so Vercel serves them as files. The database, checkout and admin run as small Vercel functions in `api/` (shared code in `lib/`). To preview the pages locally:

```bash
python3 -m http.server 8000
```

That preview has no database, so it shows the built-in pieces and WhatsApp checkout, exactly like the live site before the database is connected.

**Changing pages:** the pages, `robots.txt`, `sitemap.xml`, `site.webmanifest` and `vercel.json` are all generated by `tools/build_pages.py` from one shared header, footer and set of metadata. Edit that file, then run:

```bash
python3 tools/build_pages.py .
```

Run it again after any change to `assets/css/style.css`, `assets/js/*.js` or `assets/admin/*`. It stamps each page with a fresh version of those files, so visitors never get a stale copy.

## Admin dashboard, database and Paystack

Go to **https://adabeke.vercel.app/admin** on a phone or laptop.

| Section | What you can do |
| --- | --- |
| Overview | Sales this month (compared with last month), paid orders, orders to pack and ship, unpaid orders to follow up, and the latest orders |
| Orders | Search by name, phone, email or reference; filter by To ship, Unpaid, Shipped, Delivered or Cancelled. Open an order to move it along (New, Confirmed, Shipped, Delivered, or Cancel), see the customer's details and address, WhatsApp, call or email them with a ready-written message, keep a private note (e.g. a tracking number), mark WhatsApp orders as paid, or ask Paystack whether an online payment went through |
| Pieces | Add, edit, reorder or delete pieces. Upload photos straight from your phone (they're shrunk automatically), set the price, a fit note and a collection, and choose **Available**, **Dropping soon**, **Sold out** or **Hidden**. Below the pieces: **Collections**, each with a name, a short line, a cover photo and its pieces. The shop updates within a minute |
| Marketing | **Discount codes**: percent or naira off, with an optional minimum order, number of uses and last day; switch them off without deleting. **Early access**: everyone who signed up, with a search, WhatsApp/email buttons, "Copy all emails" and a spreadsheet download |
| Settings | Delivery options and fees shown at checkout, **prices abroad** (today's rate, your own rates, or off), Paystack status, and the webhook address to give Paystack |

### One-time setup (about 5 minutes)

The database is **Supabase** (Postgres). Either way below works:

- **Easiest, from Vercel:** open the `adabeke` project → **Storage** → **Create Database** → **Supabase**, free plan, region **East US (North Virginia)** so it sits next to the site's functions, and connect it to the project. This adds `POSTGRES_URL` for you.
- **With a Supabase project you already have:** in Supabase press **Connect**, copy the **Transaction pooler** connection string (port `6543`) and put your database password in it. In Vercel → **Settings → Environment Variables**, add it as `DATABASE_URL`.

Then:

1. **Admin password:** in Vercel → **Settings → Environment Variables**, add `ADMIN_PASSWORD` (at least 8 characters).
2. **Redeploy:** **Deployments** → `···` on the latest one → **Redeploy**.
3. Open `/admin` and sign in. The first visit creates the tables and copies in the current pieces and collections from `assets/js/products.js`.

**Supabase notes**
- The tables live in Supabase's `public` schema with **row level security on and no rules**, so Supabase's own public data API can't read or change them. Only the website (which owns the tables) can. You can still browse them in Supabase's Table Editor.
- Free Supabase projects go to sleep after a week without activity. `vercel.json` has a daily job (6:17 UTC) that opens `/api/catalogue?keepalive=1`, which touches the database and keeps it awake.

### Switching on Paystack

1. In Paystack: **Settings → API Keys & Webhooks**. Copy the **test** secret key (`sk_test_…`) first.
2. In Vercel: add it as `PAYSTACK_SECRET_KEY` in **Settings → Environment Variables**.
3. In Paystack, set the **Webhook URL** to `https://adabeke.vercel.app/api/paystack-webhook` (also shown, with a copy button, in the admin's Settings).
4. Redeploy. The bag's checkout switches to "Checkout → Pay ₦… securely" by itself, and wording on the Contact page changes to match.
5. Try a test order with one of [Paystack's test cards](https://paystack.com/docs/payments/test-payments/). When happy, swap in the **live** key (`sk_live_…`) and redeploy.

### How ordering works

- **With Paystack on:** the bag's **Checkout** asks for name, email, phone, address, a delivery option and (optionally) a discount code, then sends the customer to Paystack to pay by card, bank transfer or USSD. Customers abroad also see their total in dollars and pounds. Prices and delivery fees always come from the database, never from the browser. When the payment succeeds, Paystack tells the site (the webhook), the order is marked **Paid**, the customer lands on a "Thank you" page and gets Paystack's email receipt, and the order shows in the admin under **To ship**. Customers can still choose "Or order on WhatsApp".
- **Before Paystack (or for pieces priced on request):** "Checkout on WhatsApp" opens WhatsApp (+234 809 371 2578) with the order written out. Once the database is connected, the message includes a reference like `AB-7KQ2M9XP` and the order appears in the admin, so you can match the chat to it, fill in the customer's details and mark it paid.
- The bag is saved in the visitor's browser, and the checkout form remembers their details for next time.

### Settings it uses (Vercel environment variables)

| Name | Needed | What it is |
| --- | --- | --- |
| `DATABASE_URL` or `POSTGRES_URL` | yes | The Supabase connection string (the Vercel integration adds `POSTGRES_URL`) |
| `ADMIN_PASSWORD` | yes | The admin sign-in password. Changing it signs everyone out |
| `PAYSTACK_SECRET_KEY` | for online payment | `sk_test_…` while testing, `sk_live_…` for real payments |
| `SITE_URL` | no | Only if the site moves to its own domain, e.g. `https://adabeke.com` |

### Without a database

Nothing breaks. The shop shows the built-in pieces and collections from `assets/js/products.js` and checks out on WhatsApp; "Get early access" opens WhatsApp instead of saving to the list; prices abroad and discount codes stay off; and `/admin` shows the setup steps. If the database is ever unreachable, the shop falls back to that same list after 2.5 seconds.

### Files

| File | What it does |
| --- | --- |
| `api/catalogue.js` | The live list of pieces, delivery options and whether Paystack is on, cached for 20 seconds at Vercel's edge |
| `api/checkout.js` | Creates orders, checks discount codes and starts Paystack payments |
| `api/subscribe.js` | Early-access sign-ups (email or WhatsApp number) |
| `api/order.js` | The "Thank you" page's order details; double-checks with Paystack |
| `api/paystack-webhook.js` | Paystack's signed "payment succeeded" message |
| `api/img.js` | Photos uploaded in the admin |
| `api/admin.js` | Everything the dashboard does (sign-in, orders, pieces, settings) |
| `lib/` | Database tables, Paystack, sign-in, exchange rates (`fx.js`) and shared rules |
| `assets/admin/` | The dashboard's look and behaviour |

**Security:** the admin cookie is HttpOnly, SameSite=Strict and expires after 14 days; sign-in is limited to 8 tries per 15 minutes; changes need a header other websites can't send; webhook messages must carry Paystack's signature, and every payment is re-checked with Paystack (amount and currency included) before an order is marked paid; discount codes are checked on the server, never trusted from the browser.

### Shop features

- **Collections:** big photo cards on the home page ("Shop by collection") and filter buttons in the shop. A link like `shop.html?c=sets` opens the shop filtered. The site starts with two, **Sets** (Omalicha, Abira) and **Boubous** (Wifey); rename them, change the cover photos or add new ones in the admin. A collection with no pieces stays hidden.
- **Early access:** "Be first to the next drop" in the footer of every page, plus "Get early access" on any piece that's dropping soon. People enter an email address or a WhatsApp number (a Nigerian number like 0803… is turned into +234…). Repeat sign-ups are recognised.
- **You may also like:** each piece's details panel suggests three others, from the same collection first.
- **Discount codes:** typed at the online checkout. Each use is counted only once the order is paid.
- **Fit note:** an optional line on each piece, shown in a soft box in its details, for example how long it falls.
- **Prices abroad:** "≈ $29 · £23" next to the naira price in each piece's details and under the checkout total. By default it uses the day's market rate (from the free [currency-api](https://github.com/fawazahmed0/exchange-api), checked a few times a day); you can type your own rates or switch it off. Customers always pay in naira.

## Adding or editing pieces

Once the database is connected, use **Pieces** in the admin. Before that, edit **`assets/js/products.js`** (it's also the starting list the database copies the first time):

```js
{
  id: "new-piece",                 // used in links: shop.html?p=new-piece
  name: "Name boubou",
  colour: "Ivory",
  price: 55000,                    // or null for "Price on request"
  status: "available",             // "available", "soon", "sold_out" or "hidden"
  badge: "New",
  includes: "Sold with the scarf",
  fabric: "Chiffon",               // or null if you'd rather not say
  fit: "Free size",
  description: "One or two sentences.",
  images: ["assets/img/new-piece-1.webp", "assets/img/new-piece-2.webp"],
},
```

Portrait photos (4:5) look best, and the second photo shows when the shopper hovers. A piece with no photos shows a coloured "Photo coming soon" card.

### Photos from the shoot

The photographer's pictures live in `assets/img/shoot/`, each in two sizes: `name.webp` (1600×2000, for big screens and sharp phone screens) and `name-800.webp` (800×1000). Phones, laptops and thumbnails each get the size they need automatically, as long as a piece's photo path points at the big one (`assets/img/shoot/name.webp`).

These are ready but not in the shop yet, because the pieces need a name and price: the white boubou with orange circles (`circles-open`, `circles-side`, `circles-lean`, `circles-back`), the navy, red and orange checked boubou (`check-vine`, `check-doors`), both together (`duo-doors`), and the black shirt with gold pleated trousers (`gold-pleats`).

## Design

- **Colours:** ADA BEKE aqua `#58DADC` (from her bags and end card) for the announcement bar, the page title bands, the footer and small accents; near-black `#141414` for text and buttons; white pages. The rust of the boubou print `#C9602F` is kept for placeholders.
- **Look:** laid out after moyeafrica.com, as Ada asked: a moving announcement bar, the ADA BEKE logo centred with a small uppercase menu under it, a coloured band with each page's title, photos with their real backgrounds and no words on the clothes, small uppercase product names, outlined round-ended buttons, and a footer with the ADA BEKE name spelled out wide. ADA BEKE's own logo, photos, words and colours are used throughout; nothing is taken from Moye.
- **Type:** one font, Montserrat (the same family Moye uses), for everything; no italics. Menus, product names and buttons are small capitals with wide spacing. The ADA BEKE logo keeps its own lettering (Cinzel).
- **Motion:** kept to a minimum. Things fade up gently as they come into view, and on phones the home photos change every 5 seconds. All motion switches off for visitors who have "reduce motion" turned on.
- **Lottie:** the "choosing a dress" animation appears when the bag is empty, on the Shop page, and on the Contact page, with a shimmering placeholder until it's ready. It's served from this site (`assets/lottie/choosing.js`), played with [lottie-web](https://github.com/airbnb/lottie-web) (MIT, `assets/vendor/`), and only loads when it's needed.

## Search, sharing and metadata

- Every page has a title, description, canonical address, and share previews for WhatsApp, Instagram, X and others, using branded 1200×630 images in `assets/img/og/`.
- Structured data tells Google about the store (with WhatsApp contact and Instagram), the pages, and the contact page's questions. On the shop page, each priced piece is listed as a product with its price in naira and whether it's in stock, generated from the live list.
- `robots.txt` allows the shop pages, keeps `/admin`, `/api/` and the order page out of search engines, and points to `sitemap.xml`, which lists the four pages and their main photos.
- `site.webmanifest` plus the icons in `assets/img/icons/` let people add the site to their home screen with the aqua ADA BEKE icon.
- `404.html` is a simple "Page not found" page that Vercel shows for any wrong address.
- `vercel.json` caches photos for a day and the versioned CSS/JS for a year.

If the site moves to its own domain, change `SITE` at the top of `tools/build_pages.py` and rebuild.

## Loading

- **Skeleton loading:** while things load, the shop grid and the home page's "Handpicked for you" show shimmering placeholder cards, and every photo shows a mist shimmer until it arrives, then settles in from soft to sharp. The details panel, the bag, the order page, the dress animation and the admin dashboard do the same.
- **Safety net:** if the page script is very slow or fails, the page shows everything plainly after 4 seconds instead of waiting.

## Home photos

Three photos from the shoot, set in the `HERO_PHOTOS` list in the page builder: the circle-print boubou, Abira and Wifey, shown with their real backgrounds. Phones show one at a time (they change every 5 seconds, or swipe, or tap a dot); laptops show all three side by side. Further down, `duo-doors-wide.webp` is the wide lookbook photo and four smaller shoot photos make the collage beside the social links. To change a photo, put the new one in `assets/img/shoot/` in the two sizes described under "Photos from the shoot" and edit its line in `HERO_PHOTOS`. The announcement bar's notes are in `ANNOUNCE` at the top of the page builder.

## Speed

The home page downloads about 1 MB, most of it the sharp photos. Phones preload the first photo and fetch the others one at a time; laptops load all three. The campaign film in the home page's dark card only starts loading when it scrolls into view: phones get the portrait film (about 4 MB), laptops a landscape version (`campaign-wide.mp4`, about 6 MB) where the film plays sharp in the middle and a blurred copy of itself fills the rest of the card, because the original is portrait and only 464 pixels wide.

## Putting it online

The site runs on Vercel (https://adabeke.vercel.app), which deploys every push to the branch. GitHub Pages can't run the checkout, database or admin, so stay on Vercel.
