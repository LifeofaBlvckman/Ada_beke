# ADA BEKE — website

*Chic • relaxed • Elegance.* The website for **ADA BEKE**, the free-size fashion brand (Instagram [@byadabeke](https://www.instagram.com/byadabeke/)): four shop pages, online checkout with Paystack, and an admin dashboard for orders and pieces.

| Page | File | What's on it |
| --- | --- | --- |
| Home | `index.html` | Full-screen photo slideshow with the headline on top, the brand story, a swipeable "Handpicked for you" slider, a note from Ada Beke, and a "made in Nigeria" banner |
| Shop | `shop.html` | All pieces with filters, a product details panel, and the bag |
| About | `about.html` | Brand story, the full "We're back" letter, Chic / relaxed / Elegance |
| Contact | `contact.html` | How to order, a WhatsApp contact form, the free-size guide and questions |
| Your order | `order.html` | Where Paystack sends customers after paying: "Thank you" with their order, or "Payment not completed" |
| Admin | `admin/` | The dashboard: sales, orders, pieces, delivery fees (password protected, hidden from search engines) |

The pages are plain HTML, CSS and JavaScript, and the built pages are committed, so Vercel serves them as files. The database, checkout and admin run as small Vercel functions in `api/` (shared code in `lib/`). To preview the pages locally:

```bash
python3 -m http.server 8000
```

That preview has no database, so it shows the built-in pieces and WhatsApp checkout, exactly like the live site before the database is connected.

**Changing pages:** the pages, `robots.txt`, `sitemap.xml`, `site.webmanifest` and `vercel.json` are all generated by `tools/build_pages.py` from one shared header, footer and set of metadata. Edit that file, then run:

```bash
python3 tools/build_pages.py .
```

Run it again after any change to `assets/css/style.css`, `assets/js/*.js` or `assets/admin/*`. It stamps each page with a fresh version of those files, so visitors never get a stale copy.

## Admin dashboard, database and Paystack

Go to **https://adabeke.vercel.app/admin** on a phone or laptop.

| Section | What you can do |
| --- | --- |
| Overview | Sales this month (compared with last month), paid orders, orders to pack and ship, unpaid orders to follow up, and the latest orders |
| Orders | Search by name, phone, email or reference; filter by To ship, Unpaid, Shipped, Delivered or Cancelled. Open an order to move it along (New, Confirmed, Shipped, Delivered, or Cancel), see the customer's details and address, WhatsApp, call or email them with a ready-written message, keep a private note (e.g. a tracking number), mark WhatsApp orders as paid, or ask Paystack whether an online payment went through |
| Pieces | Add, edit, reorder or delete pieces. Upload photos straight from your phone (they're shrunk automatically), set the price, and choose **Available**, **Dropping soon**, **Sold out** or **Hidden**. The shop updates within a minute |
| Settings | Delivery options and fees shown at checkout, Paystack status, and the webhook address to give Paystack |

### One-time setup (about 5 minutes, all in Vercel)

1. **Database:** open the `adabeke` project in Vercel → **Storage** → **Create Database** → **Neon** (Postgres), free plan. Choose the region **Washington, D.C. (iad1)** so it sits next to the site's functions, and connect it to the project. This adds `DATABASE_URL` for you.
2. **Admin password:** **Settings → Environment Variables** → add `ADMIN_PASSWORD` (at least 8 characters).
3. **Redeploy:** **Deployments** → `···` on the latest one → **Redeploy**.
4. Open `/admin` and sign in. The first visit creates the tables and copies in the current pieces from `assets/js/products.js`.

### Switching on Paystack

1. In Paystack: **Settings → API Keys & Webhooks**. Copy the **test** secret key (`sk_test_…`) first.
2. In Vercel: add it as `PAYSTACK_SECRET_KEY` in **Settings → Environment Variables**.
3. In Paystack, set the **Webhook URL** to `https://adabeke.vercel.app/api/paystack-webhook` (also shown, with a copy button, in the admin's Settings).
4. Redeploy. The bag's checkout switches to "Checkout → Pay ₦… securely" by itself, and wording on the Contact page changes to match.
5. Try a test order with one of [Paystack's test cards](https://paystack.com/docs/payments/test-payments/). When happy, swap in the **live** key (`sk_live_…`) and redeploy.

### How ordering works

- **With Paystack on:** the bag's **Checkout** asks for name, email, phone, address and a delivery option, then sends the customer to Paystack to pay by card, bank transfer or USSD. Prices and delivery fees always come from the database, never from the browser. When the payment succeeds, Paystack tells the site (the webhook), the order is marked **Paid**, the customer lands on a "Thank you" page and gets Paystack's email receipt, and the order shows in the admin under **To ship**. Customers can still choose "Or order on WhatsApp".
- **Before Paystack (or for pieces priced on request):** "Checkout on WhatsApp" opens WhatsApp (+234 809 371 2578) with the order written out. Once the database is connected, the message includes a reference like `AB-7KQ2M9XP` and the order appears in the admin, so you can match the chat to it, fill in the customer's details and mark it paid.
- The bag is saved in the visitor's browser, and the checkout form remembers their details for next time.

### Settings it uses (Vercel environment variables)

| Name | Needed | What it is |
| --- | --- | --- |
| `DATABASE_URL` | yes | Added by the Neon integration (`POSTGRES_URL` also works) |
| `ADMIN_PASSWORD` | yes | The admin sign-in password. Changing it signs everyone out |
| `PAYSTACK_SECRET_KEY` | for online payment | `sk_test_…` while testing, `sk_live_…` for real payments |
| `SITE_URL` | no | Only if the site moves to its own domain, e.g. `https://adabeke.com` |

### Without a database

Nothing breaks. The shop shows the built-in pieces from `assets/js/products.js` and checks out on WhatsApp, and `/admin` shows the setup steps. If the database is ever unreachable, the shop falls back to that same list after 2.5 seconds.

### Files

| File | What it does |
| --- | --- |
| `api/catalogue.js` | The live list of pieces, delivery options and whether Paystack is on, cached for 20 seconds at Vercel's edge |
| `api/checkout.js` | Creates orders and starts Paystack payments |
| `api/order.js` | The "Thank you" page's order details; double-checks with Paystack |
| `api/paystack-webhook.js` | Paystack's signed "payment succeeded" message |
| `api/img.js` | Photos uploaded in the admin |
| `api/admin.js` | Everything the dashboard does (sign-in, orders, pieces, settings) |
| `lib/` | Database tables, Paystack, sign-in and shared rules |
| `assets/admin/` | The dashboard's look and behaviour |

**Security:** the admin cookie is HttpOnly, SameSite=Strict and expires after 14 days; sign-in is limited to 8 tries per 15 minutes; changes need a header other websites can't send; webhook messages must carry Paystack's signature, and every payment is re-checked with Paystack (amount and currency included) before an order is marked paid.

## Adding or editing pieces

Once the database is connected, use **Pieces** in the admin. Before that, edit **`assets/js/products.js`** (it's also the starting list the database copies the first time):

```js
{
  id: "new-piece",                 // used in links: shop.html?p=new-piece
  name: "*Name* boubou",           // *stars* = italic
  colour: "Ivory",
  price: 55000,                    // or null for "Price on request"
  status: "available",             // "available", "soon", "sold_out" or "hidden"
  badge: "New",
  includes: "Sold with the scarf",
  fabric: "Chiffon",               // or null if you'd rather not say
  fit: "Free size",
  description: "One or two sentences.",
  images: ["assets/img/new-piece-1.webp", "assets/img/new-piece-2.webp"],
},
```

Portrait photos (4:5) look best, and the second photo shows when the shopper hovers. A piece with no photos shows a coloured "Photo coming soon" card.

## Design

- **Colours:** brand aqua `#58DADC` (taken from the ADA BEKE bags and end card), navy `#0F2A4A` (from the Omalicha fabric), and a pale aqua mist `#EAF8F8`, plus the rust of the boubou circle print `#C9602F` as an accent.
- **Type:** Bodoni Moda italic (the high-contrast "fashion magazine" serif) for the headline and emphasised words, Jost (a Futura-style geometric sans) for headings and text, and Cinzel for the ADA BEKE wordmark.
- **Motion:** the home headline appears letter by letter, then drifts up and fades as you scroll while the photos slowly push in. Section words appear one by one, photos fade up and drift gently (parallax), the story paragraph lights up word by word, and an aqua ADA BEKE panel wipes between pages. On a computer, a "View" bubble follows the mouse over pieces. All motion switches off for visitors who have "reduce motion" turned on.
- **Lottie:** the "choosing a dress" animation appears when the bag is empty, on the Shop page, and on the Contact page. It's served from this site (`assets/lottie/choosing.js`), played with [lottie-web](https://github.com/airbnb/lottie-web) (MIT, `assets/vendor/`), and only loads when it's needed.

## Search, sharing and metadata

- Every page has a title, description, canonical address, and share previews for WhatsApp, Instagram, X and others, using branded 1200×630 images in `assets/img/og/`.
- Structured data tells Google about the store (with WhatsApp contact and Instagram), the pages, and the contact page's questions. On the shop page, each priced piece is listed as a product with its price in naira and whether it's in stock, generated from the live list.
- `robots.txt` allows the shop pages, keeps `/admin`, `/api/` and the order page out of search engines, and points to `sitemap.xml`, which lists the four pages and their main photos.
- `site.webmanifest` plus the icons in `assets/img/icons/` let people add the site to their home screen with the aqua ADA BEKE icon.
- `404.html` is a branded "Lost your way?" page that Vercel shows for any wrong address.
- `vercel.json` caches photos for a day and the versioned CSS/JS for a year.

If the site moves to its own domain, change `SITE` at the top of `tools/build_pages.py` and rebuild.

## Designs

The decorations come from the brand itself:
- **Rings:** the circle print on the white & brown boubou, slowly turning.
- **Arch frames:** the arch behind the Omalicha mannequin.
- **Wavy section edges:** the curved white bench in the studio photos.
- **Aqua sparkles:** they twinkle.
- **Outlined words:** large outlined words drift behind some sections.

Other details:
- Photos are revealed by an aqua panel sliding off them.
- Text pops in one piece after another.
- Buttons lean towards the mouse.
- A thin aqua line at the top shows how far down the page you are.

All movement stops for visitors with "reduce motion" on.

## Loading

- **Skeleton loading:** while things load, the shop grid and the "Handpicked" slider show shimmering placeholder cards, and every photo shows a mist shimmer until it arrives, then settles in from soft to sharp. The details panel, the bag, the order page, the dress animation and the admin dashboard do the same.
- **Safety net:** if the page script is very slow or fails, the page shows everything plainly after 4 seconds instead of waiting.

## Home slideshow

The opening photos live in `assets/img/hero-1-white-brown.webp` … `hero-4-ash.webp`, each with a tiny `-blur` copy used for the soft background on wide screens. To change a photo, replace both files (portrait 4:5, about 1024×1280) and keep the names, or edit the `slides` list in the page builder. Each slide is marked `light` or `dark` so the words switch between navy and white to stay readable. Photos change every 5.5 seconds, visitors can swipe on a phone, and the slideshow pauses when it's off screen.

## Speed

The home page downloads about 500 KB on a phone: the first photo is preloaded, and the others load in the background. The aqua curtain never waits for fonts, and moving between pages takes well under a second.

## Putting it online

The site runs on Vercel (https://adabeke.vercel.app), which deploys every push to the branch. GitHub Pages can't run the checkout, database or admin, so stay on Vercel.
